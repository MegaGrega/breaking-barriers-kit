# AgentCore + Strands + Bedrock agent

Optimise for: a working agent reachable by the demo frontend as early as possible, then improve. Never let deployment block the demo: local first, cloud second.

## 0. Preflight (run these, report results, fix before scaffolding)

```bash
aws sts get-caller-identity          # creds valid? which account?
echo $AWS_REGION                     # must be set; us-east-1 or us-west-2 usually have the most models
node --version                       # >= 20.12
uv --version
agentcore --version                  # npm i -g @aws/agentcore
aws bedrock list-inference-profiles --region $AWS_REGION --query "inferenceProfileSummaries[].inferenceProfileId" --output text
```

- Event accounts are **ephemeral**: credentials are usually pasted as `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` and expire every few hours. On `ExpiredToken`, tell the user to re-copy them from the event portal; never hardcode them in files.
- Windows: if `agentcore --version` errors, an old pip `bedrock-agentcore-starter-toolkit` is shadowing it → `pip uninstall bedrock-agentcore-starter-toolkit`, open a new terminal.
- Python: if the system Python is very new (3.13+/3.14) and a dependency fails to install, pin the project with `uv python pin 3.12`.
- Model IDs: pick from the `list-inference-profiles` output (cross-region profiles look like `us.amazon.nova-...` or `us.anthropic.claude-...`). Do not guess IDs from memory.

## 1. Scaffold (use the official template, then edit it)

```bash
agentcore create --name <ProjectName> --template agent-python-strands
cd <ProjectName>
```

This creates `app/agent/main.py` (entrypoint + Strands agent), `app/agent/model/load.py` (model), `app/agent/memory/session.py` (AgentCore Memory), and `agentcore/agentcore.json` (resources). **Read the generated files before changing them** — the template evolves; follow what it generated, not this skill's memory of it.

Then:
1. Set the model in `model/load.py` from the preflight list. Default to a fast, cheap model (Nova Lite/Pro class or Claude Haiku/Sonnet class) for iteration.
2. Write the system prompt from `docs/brief.md` (persona, job to be done, constraints, tone, reading level, languages, what to refuse / escalate).
3. `git add -A && git commit -m "scaffold"` before any big change.

## 2. Run locally

```bash
agentcore dev --mode browser        # hot reload + agent inspector in the browser
agentcore invoke --runtime agent --local --payload '{"prompt":"<golden path step 1>"}'
```

Test the golden-path prompts from the brief immediately. Save them in `tests/golden.jsonl` (one `{"prompt": ..., "expect": ...}` per line) so every change can be re-checked.

## 3. Tools

Strands tools are plain Python functions with the `@tool` decorator and a docstring (the docstring is what the model sees — write it like an API description: when to use, args, return). Add tools to the `Agent(tools=[...])` list in `main.py`.

Good hackathon tools: lookup in a CSV/JSON of the nonprofit's programs or resources; eligibility rules as code (deterministic, not LLM); create a record (write to DynamoDB or a local JSON file in demo); send an SMS/email (stub it in the demo and log); geocode / find nearest location.

Rule: anything that must be correct (eligibility, dosage, dates, money) is computed in a tool, not generated by the model. Say this in the pitch.

## 4. Knowledge over the nonprofit's documents (RAG)

Pick the lightest option that works:
- **< ~50 pages of text**: put it in the system prompt or a `search_docs` tool doing keyword search over local files. Zero infrastructure, works in 10 minutes.
- **More, or PDFs/scans**: Bedrock Knowledge Base with an S3 data source (S3 Vectors as the vector store is the cheapest/fastest to set up; OpenSearch Serverless is slower to provision and costs more while idle — avoid for a hackathon). Add a `retrieve` tool that calls `bedrock-agent-runtime` `retrieve` and returns passages **with source names** so answers can cite them.
- Scanned forms: Textract first, then index the text.

Always return citations to the UI. Judges and nonprofits trust "according to <doc>, page 3" far more than fluent text.

## 5. Memory

The template includes AgentCore Memory. Use short-term memory for the conversation, long-term only if the brief needs "remember this person across visits" (e.g. caregiver support, case management). Never store sensitive data in memory in the demo; use synthetic personas.

## 6. Deploy

```bash
agentcore build                  # validate
agentcore deploy                 # first deploy bootstraps CDK; takes several minutes
agentcore status
agentcore invoke --runtime agent --payload '{"prompt":"hello"}'
agentcore logs runtime --since 30m --level error
```

If deploy fails on permissions in the event account, do not burn more than 20 minutes: ask an on-site AWS Solutions Architect (that is what they are there for) and keep demoing from local in the meantime. Show deployed-ness with the architecture diagram + `agentcore status` output if it never gets fixed.

## 7. Wire to the frontend

Expose one function the UI calls: `ask(prompt, session_id) -> {text, citations, tool_calls}`. Locally it calls the dev server; deployed it calls `invoke_agent_runtime` via boto3 (`bedrock-agentcore` client). Keep a `DEMO_MODE=replay` switch (see the demo-frontend skill).
